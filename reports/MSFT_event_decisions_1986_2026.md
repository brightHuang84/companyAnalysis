## 1986–1989

### 1986-02 · 公司 · 总部迁至雷德蒙德园区

**效果判定：兑现** · 新闻对照：公司史/校园落成报道 · 事实核验：属实

**当时背景**

微软已从 Albuquerque 迁到贝尔维尤，MS-DOS 授权随 IBM PC 兼容机铺开，人数和产品线撑不住分散租楼。个人电脑行业正在从爱好者市场变成企业采购，投资人开始要求看得见的总部与治理。园区选址发生在 IPO 前一个月，属于上市包装的一部分，也是真实的扩产需求。

**决策原因**

公开口径是把研发、支持、销售收拢到一座校园，靠近西雅图人才。可核对的约束是：需要期权激励的物理中心、需要向承销商展示可持续经营实体。盖茨仍要保持对工程文化的控制，园区比租用市中心写字楼更容易按自己的规矩建。

*原因核验：搬迁与园区落成属实；把搬迁主要解释成「为上市做样板」属于推断，未见到当时董事会纪要。*

**决策目录 · 当时可走的路**

- 继续在贝尔维尤分散租楼
- 买现成园区立刻搬
- 在雷德蒙德自建/启用专用校园并在上市前完成搬迁

**决策目录 · 实际拍板**

- 选定雷德蒙德作为长期总部
- 上市前完成搬迁，避免招股期间还在搬家
- 采用校园而不是城市中心写字楼，把生活与工作绑在同一地点

**近端效果**

上市路演时公司有可参观的总部；招聘话术从「小软件店」变成「有校园的平台公司」。

**最终效果**

雷德蒙德成为此后四十年决策和工程中心。校园模式强化了内部闭环，也让后来的远程/多元文化转型更慢。效果按选址目标兑现。

### 1986-03-13 · 资本 · 纳斯达克 IPO，发行价 21 美元，融资约 6100 万美元

**效果判定：兑现** · 新闻对照：Goldman Sachs 承销记录；Seattle Times 公司年表 · 事实核验：发行价与融资额多源一致；收盘价报道有 28 与 35.50 两种口径

**当时背景**

PC 兼容机出货上升，MS-DOS 授权费可预期，但微软仍是私人公司：早期员工要流动性，收购要用股票当货币，IBM 关系又不能保证永远独占操作系统。1980 年代科技股喜欢纳斯达克。盖茨家族和内部人需要在不失去控制权的前提下打开公众市场。

**决策原因**

给员工期权套现通道、提高并购支付能力、接受公众公司披露纪律以换资本。发行价 21 美元、融资约 6100 万美元，规模相对后来的微软很小，说明当时要的是市场身份和期权机制，不是一次填满金库。高盛承销，走的是主流机构路线。

*原因核验：发行价、融资金额、承销商多源一致。控制权安排的「内心动机」来自后续股权结构，不是招股书里的一句原话。*

**决策目录 · 当时可走的路**

- 继续私有，靠利润自我供血
- 上纽约证券交易所走传统蓝筹
- 上纳斯达克、小规模发行、内部人保留控制

**决策目录 · 实际拍板**

- 选择纳斯达克而不是纽交所
- 发行价定 21 美元，融资约 6100 万美元
- 高盛主承销
- 盖茨及内部人保留多数控制，不把公司卖成职业经理人公司

**近端效果**

首日放量。市值大约 7.8 亿美元量级。员工期权开始有公开定价。收盘价报道有 28 与 35.50 两种口径，不能用单一收盘价讲「翻了几倍」。

**最终效果**

公众公司身份让后来的反垄断、并购和回购都在 SEC 纪律下进行。上市本身兑现；它没有自动保证产品垄断——垄断是 1990 年代 Windows/Office 做出来的。

### 1987-04-02 · 产品 · 宣布与 IBM 的 OS/2

**效果判定：部分兑现** · 新闻对照：当代行业报道 · 事实核验：属实

**当时背景**

IBM 要把 PC 从开放兼容机拉回可控平台，OS/2 被定位为 DOS 接班人。微软靠 DOS 赚钱，但不能公开与 IBM 决裂：企业客户仍听 IBM。Windows 1.x/2.x 当时还是 DOS 上的壳，口碑和销量都远不够当「下一代操作系统」。行业里同时存在 Unix 工作站这条企业线。

**决策原因**

维持与最大客户兼标准制定者 IBM 的关系，进入企业级操作系统，对冲 Windows 失败。公开合作可以继续拿到 IBM 渠道；私下继续做 Windows，避免把全部未来押在 IBM 的日程上。

*原因核验：联合宣布属实。双线对冲是后来分道扬镳所证实的行为，不是 1987 年新闻稿原句。*

**决策目录 · 当时可走的路**

- 放弃 Windows，全力 OS/2
- 拒绝 IBM，只做 Windows
- 公开联合 OS/2，同时继续 Windows 与自研 NT 内核

**决策目录 · 实际拍板**

- 与 IBM 宣布 OS/2 合作
- 不停止 Windows 消费线
- 在合作破裂后把企业内核转到自研 NT，而不是跟 IBM 的 OS/2 走到底

**近端效果**

企业客户短期内把 OS/2 当成正统下一代；Windows 仍被看成业余图形层。

**最终效果**

API、进度和利益冲突后双方分道。OS/2 边缘化，Windows 赢了桌面，NT 成为服务器和后来 Azure 的技术祖宗。联盟失败，技术对冲部分兑现。

### 1987-07 · 并购 · 收购 Forethought（PowerPoint）

**效果判定：兑现** · 新闻对照：公司史 · 事实核验：属实

**当时背景**

桌面生产力和 Word、Excel 单打，演示文稿被 Aldus/Harvard Graphics 等占据。Forethought 的 PowerPoint 已有产品，微软自己从零做演示会慢。Office 作为「套装」的想法还没有完全公开成型，但已经需要第三件套来堵住缺口。

**决策原因**

买现成演示产品比自研快，并能把 Word/Excel 的文件和销售渠道立刻接上。收购成本相对自建团队更可控，也避免让竞争对手先把演示标准定死。

*原因核验：收购 Forethought 属实。将其解释为「预先为 Office 套装铺路」与 1989/1990 套装发布时间线相符，但 1987 年董事会是否已写下「三件套」计划未独立核实。*

**决策目录 · 当时可走的路**

- 自研演示软件
- 与 Aldus 等授权/合作
- 直接买下 PowerPoint 团队与代码

**决策目录 · 实际拍板**

- 收购 Forethought，拿下 PowerPoint
- 纳入微软应用事业部，而不是当独立品牌长期运营
- 后续用套装定价把三件套绑在一起卖

**近端效果**

微软补齐演示缺口，销售可以开始讲「文书+表格+幻灯」。

**最终效果**

Office 成为比 Windows 更稳的利润中心之一。没有这次收购，套装策略会晚、会碎。按补齐产品线的目标兑现。

### 1987-12-09 · 产品 · Windows 2.0

**效果判定：部分兑现** · 新闻对照：产品发布 · 事实核验：属实

**当时背景**

Macintosh 已经证明图形界面能卖给非技术用户；PC 这边仍是字符 DOS。Windows 1.0 窗口不能重叠，被当成玩具。Intel 286/386 开始让图形界面在 PC 上不那么卡。应用开发者还在观望：为 Windows 写程序是否值得。

**决策原因**

必须让 Windows 看起来更像「真的操作系统壳」：重叠窗口、更好的图形，才能留住独立软件开发商，并在 IBM OS/2 交付之前占住 PC 图形入口。公开口径是改进界面；竞争压力来自 Mac 和即将到来的 OS/2。

*原因核验：发布属实。把 2.0 的主要动机写成「抢在 OS/2 之前」是竞争时间线推断。*

**决策目录 · 当时可走的路**

- 停 Windows，等 OS/2
- 只做驱动和工具，不推界面壳
- 继续迭代 Windows，用 2.0 补重叠窗口等基础能力

**决策目录 · 实际拍板**

- 发布 Windows 2.0，仍运行在 DOS 之上
- 改进窗口模型和图形，吸引应用移植
- 不把 2.0 定位成企业服务器操作系统

**近端效果**

仍然不是主流。苹果随后以界面相似起诉，说明它已经像到足以引发法律风险，但还没像到赢得市场。

**最终效果**

2.0 是 3.0 爆发前的过渡。产品本身未打开市场，却保留了 API 和 OEM 关系。按「赢市场」未兑现，按「不断线」兑现。

### 1988-03 · 诉讼 · 苹果起诉 Windows 抄袭 Mac 界面

**效果判定：兑现** · 新闻对照：NYT 1988-03-24 披露 1985 年协议 · 事实核验：诉讼与报道属实

**当时背景**

苹果靠图形界面建立 Mac 溢价，最怕 PC 阵营把同样的交互做便宜。微软曾与苹果有过 1985 年相关协议，《纽约时报》1988-03-24 披露过。Windows 2.0 让「像 Mac」变得可视化。这是知识产权战，也是平台战。

**决策原因**

微软的决策不是起诉，而是应诉并继续卖 Windows：若因界面诉讼停更，等于把图形 PC 让给苹果或 IBM。法律策略是主张 1985 年许可覆盖了视觉元素，并把争议拖到 Windows 3.x 已经铺开之后。

*原因核验：诉讼与 1985 年协议报道属实。具体和解/许可条款的每一句覆盖范围，未在此台账核对原合同。*

**决策目录 · 当时可走的路**

- 停更 Windows 图形界面，改走字符或完全不同的交互
- 高价向苹果再买一份全面许可
- 应诉，主张已有许可，同时加速 Windows 装机

**决策目录 · 实际拍板**

- 应诉，不承认抄袭成立
- 继续发布和授权 Windows
- 把法律战当成经营成本，而不是产品路线否决项

**近端效果**

诉讼成为行业新闻，OEM 短暂观望，但没有出现大规模停售 Windows。

**最终效果**

微软胜诉。图形界面在 PC 上不再被苹果的外观专利墙挡住，为 3.0/95 铺路。法律目标兑现。

## 1990–1999

### 1990-05-22 · 产品 · Windows 3.0

**效果判定：兑现** · 新闻对照：Seattle Times 年表 · 事实核验：属实

**当时背景**

386 PC 降价，VGA 普及，内存够跑图形界面。Lotus、WordPerfect 还在 DOS 字符里赚钱，对 Windows 移植慢。OS/2 对企业客户承诺过多、交付乱。独立软件商需要一个「已经有用户」的图形平台，而不是 IBM 的下一代故事。

**决策原因**

把 Windows 从壳做成事实上的 PC 图形标准：程序管理器、更好的内存管理、对 386 的利用。目的是让应用开发商先为 Windows 写，而不是为 OS/2 或纯 DOS。公开是产品发布；战略是锁定 ISV。

*原因核验：发布日与市场爆发属实。ISV 锁定作为主因，有大量当代报道支持，不是单源。*

**决策目录 · 当时可走的路**

- 继续小步修补 2.x
- 把资源转到 OS/2 2.0
- 把 3.0 当成真正的平台发布，压 OEM 预装、压 ISV 移植

**决策目录 · 实际拍板**

- 1990-05-22 正式发布 Windows 3.0
- 用大规模营销和 OEM 预装铺量
- 把 API 稳定性当成吸引 Excel/Word for Windows 和第三方的卖点

**近端效果**

图形界面第一次在 IBM PC 兼容机上真正普及，Windows 从附件变成买电脑时会问的东西。

**最终效果**

桌面标准从此偏向微软。Office、IE、后来的反垄断都建立在 3.0 打开的装机量上。产品目标兑现，并制造了下一阶段的监管风险。

### 1990-06 · 监管 · FTC 启动是否构成软件垄断的调查

**效果判定：部分兑现** · 新闻对照：Seattle Times：FTC 2-2 僵局未立案 · 事实核验：属实

**当时背景**

Windows 3.0 刚证明微软可以左右 PC 软件生态，OEM 授权条款、应用捆绑和「是否兼容」的话语权引起美国竞争当局注意。软件业当时几乎没有成熟的反垄断判例，FTC 先动手。微软已是上市四年的公众公司，调查本身就会进新闻。

**决策原因**

这是监管发起，不是公司主动决策。微软当时的决策是如何应对：配合调查、不主动拆分产品、继续用授权扩张。公开口径是否认垄断；内部选择是把法律战拖到产品既成事实之后。

*原因核验：FTC 立案与 2-2 僵局、转交司法部，西雅图时报等记录属实。微软内部「拖到既成事实」是后续 1994/1998 行为模式的回溯，不是 1990 年公开会议记录。*

**决策目录 · 当时可走的路**

- 主动拆开系统与应用、改授权条款以求早结案
- 全面对抗、拒绝提供文件
- 有限配合调查，产品策略不改，等待委员会僵局

**决策目录 · 实际拍板**

- 应调查，不公开认垄断
- 不在 1990 年主动拆 Office 或改变 OEM 核心条款
- 把主战场转到司法部周期（FTC 未能立案之后）

**近端效果**

FTC 委员 2-2 未立案，调查转给司法部。产品节奏几乎未停。

**最终效果**

第一次监管交锋以「没立案」结束，强化了后来「先做后谈」的习惯。对公司短期有利，给 1998 年大案留了证据链。应对目标部分兑现，长期监管风险未解除。

### 1990-11-19 · 产品 · Office 捆绑 Word/Excel/PowerPoint（另有 1989-08-01 最早套装口径）

**效果判定：兑现** · 新闻对照：Seattle Times；Windows Club 产品史 · 事实核验：套装策略属实；首次发布月有 1989/1990 两说

**当时背景**

Word、Excel、PowerPoint 已齐，但用户仍可只买 Lotus 1-2-3 或 WordPerfect。套装可以把平均售价压到单件对手难以跟的位置，并让文件格式互相依赖。另有 1989-08-01 最早套装口径，说明捆绑试验早于「Office」品牌的主流叙事。

**决策原因**

用套装价消灭单件冠军：顾客为了表格愿意带上文字和演示，竞争对手必须三线同时打。渠道上一个 SKU 比三个好推。公开是「集成生产力」；价格结构才是杀伤力。

*原因核验：套装策略属实；首次发布月 1989/1990 两说。把原因写成「消灭 Lotus/WordPerfect」有大量行业史支持，不是财报原句。*

**决策目录 · 当时可走的路**

- 三件产品继续分开定价、分开渠道
- 只做松散折扣券
- 正式套装、统一升级周期、文件互相锁

**决策目录 · 实际拍板**

- 推出 Office 套装（Word/Excel/PowerPoint）
- 套装价显著低于三件单买之和
- 后续把升级、宏、文件格式和销售激励对齐到套装而不是单件

**近端效果**

单件对手开始丢企业协议。Office 成为采购单位。

**最终效果**

生产力套件市场被收成微软一家的纪律。这是比 IE 更早、更赚钱的捆绑。按竞争目标兑现，成为后来「把 Teams 塞进 365」的模板。

### 1991-09 · 公司 · 成立 Microsoft Research

**效果判定：兑现** · 新闻对照：微软新闻稿 · 事实核验：属实

**当时背景**

公司利润高、桌面已站住，但图形、自然语言、网络还没有现成产品线。贝尔实验室式的长期研究能吸引科学家，也能当作「我们不是只会拷贝」的公关。同时 Unix/学术圈看不起 PC 软件公司。

**决策原因**

建立可发表论文、可做十年题目的机构，对冲产品部门的短周期。公开口径是基础研究；也有招聘和声望动机。盖茨时期愿意用利润养不立刻赚钱的实验室。

*原因核验：成立属实。具体首年预算与课题清单未在本台账核对原始新闻稿全文。*

**决策目录 · 当时可走的路**

- 只在产品组做改进，不设独立研究
- 赞助大学而不自建
- 自建 Microsoft Research，长期编制

**决策目录 · 实际拍板**

- 1991 年成立 Microsoft Research
- 放在产品线旁边而不是完全隔离成基金会
- 允许做图形、NLP 等十年级题目

**近端效果**

招聘到一批不愿进「应用工厂」的研究者，论文开始出现在学术会议。

**最终效果**

研究有成果也有空转。对后来的云、AI 有人才输送，但不能把 Copilot 直接记成 1991 年就规划好的。机构目标兑现，转化率无法在本条量化。

### 1992-04-06 · 产品 · Windows 3.1

**效果判定：兑现** · 新闻对照：产品发布 · 事实核验：属实

**当时背景**

### 1994-07 · 监管 · 与司法部达成同意令：不得把其他产品绑死 Windows 授权
